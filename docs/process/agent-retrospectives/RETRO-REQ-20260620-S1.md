## 3) Agent Findings

### po-analyst (Phase 1, ran twice)

- **What went right:** GATE0 did exactly its job. The agent validated the arki-seeded contract against **live vault data** before writing the REQ, found `status: mapped` in `wacertificadonodeudor.md`, counted the live distribution (`onboarding`×5, `active`×2, `mapped`×1), and **BLOCKED** rather than writing a REQ on a contract that would throw at runtime. It also caught three low-impact data observations the same way (A1 empty-string-as-absent; A2 missing `repo_url` in the seed; A3 duplicate `path` across `plugginsqlagent.md`/`dbcanvas.md`) and resolved them with safe defaults. The endpoint-scope decision (no `/api/projects/:name` — read the detail shell from the list cache) was correct and avoided pre-cutting a response shape S2–S4 own.
- **What failed:** Nothing in the agent's own behavior. The rewrite (one extra ~40K-token pass) was caused by an **upstream** defect: arki guessed an enum vocabulary for an externally-owned field.
- **Instruction update:** none for po-analyst. Reinforce the pattern as a reusable lesson (see §5, LL-007): *validate a seeded contract against live data before freezing*. GATE0 already does this; generalize it so it's an explicit GATE0 check, not an emergent behavior.

### arki (root cause of the GATE0 loop — bootstrap layer)

- **What failed:** Two recurring scaffold gaps, both confirmed across cycles:
  1. **Enumerated an externally-owned field.** `ProjectSummary.status` was seeded as a closed `z.enum([...])` even though the `status` vocabulary is owned by the vault/framework, not by kuraka-control. The app is a *reader* of that registry; the contract must not throw or drop a project when the vault introduces a new status. This is the inverse of the legitimate enum case (`enums_for_states` governs the app's **own** state machines — e.g. the triage model — not mirrored external fields).
  2. **camelCase prop on a contract-mirroring component** (`kurakaVersion`) + a **local closed `ProjectStatus` union**, both decided before the registry seam existed — forcing a rename + union-deletion at the freeze.
- **Instruction update (project-layer, preferred):** add a convention entry distinguishing *app-owned* enums (do enum) from *externally-owned mirrored* fields (use `z.string()` or a documented open union + UI-level known-set). See §6 patch and §5 LL-007/LL-008. arki should also mirror frontmatter casing 1:1 in seeded component props (no camelCase boundary for a pure projection).

### story-refiner (Phase 2)

- **What went right:** Translated the GATE0 resolution into a tight, frozen contract in the story (status `z.string()`, `governance: z.literal("project")`, `kuraka_version: z.coerce.string()`), an explicit casing decision, and a compact AC set (33 AC / 15 files) with exact file paths and the precise `KNOWN_STATUS_VARIANT` name/values. Notably it **pre-stated the `<Link>` SPA-nav idiom** (AC-16) and the inert-nav `aria-disabled` requirement (AC-23) — both lessons carried from the S12 RETRO — so the implementer had no ambiguity. Also correctly fenced the Sidebar as co-located (no premature shared-layout extraction).
- **What failed:** Nothing material. (The `aria-disabled` AC was present but still slipped past Phase 4 — that is an implementer/review gap, not a refinement gap.)
- **Instruction update:** none. Positive reinforcement: pre-stating cross-cycle idioms in AC is exactly the desired feedback loop.

## 4) Systemic Issues

1. **`backend/src/index.ts` is not testable by default.** It is a side-effecting bootstrap with no exported `createApp()` factory, so the integration test had to reconstruct an equivalent app inline (`_makeApp`). This is duplicated app-wiring that will drift from the real `index.ts`. **Fix:** the scaffold should export `createApp()` (pure app assembly) and have `index.ts` call `createApp().listen(...)`. Affects every future backend story with an integration test. Confirm in S2.
2. **`backend/` has no eslint config** (pre-existing arki scaffold gap) → `make lint` fails on the backend workspace. The **same class of gap was seen in S12** (eslint v9 installed with no config file), so this is now a **recurring arki bootstrap defect**, not a one-off. **Fix:** add `backend/eslint.config.js` in a small follow-up; patch arki to seed an eslint config for every workspace it scaffolds.
3. **arki seeds contracts by guessing, not by validating against live data.** The `status` enum (this cycle) and the camelCase `kurakaVersion` prop both came from arki assuming a shape the live source contradicts. GATE0 caught it, but arki could avoid generating the BLOCKER in the first place by sampling live data for any field projected from an external source. (Root cause of the only preventable loop this cycle.)
4. **Detail shell has no shared sidebar/layout** — different chrome than `/projects`. Deliberately deferred (story §Technical Notes), but it is now due: S2 introduces the second sidebar page. **Fix:** extract a shared layout in S2 (code-review SUGGESTION 9).
5. **Env friction (not a code defect):** port collision with an unrelated project's Vite on `localhost:5174`, resolved via `BACKEND_PORT=5184`. Both the Express port and the Vite `/api` proxy already read `BACKEND_PORT`, so no source change was needed. Worth a one-line note in the dev README so the next operator doesn't debug it.

## 5) Workflow Improvements (Concrete) + Proposed Lessons

1. **Generalize the GATE0 live-data check (LL-007).** Make "validate any seeded/inherited contract field that mirrors an external source against live data before the schema freeze" an explicit po-analyst GATE0 step, not emergent behavior. It caught a day-one crash this cycle for the cost of one analysis pass.
2. **Codify the app-owned vs externally-owned enum distinction (LL-008).** `enums_for_states` is correct for the app's own state machines (triage); it is *wrong* for mirrored external fields (vault `status`). Future stories must apply the right one. Add a convention entry (§6).
3. **Export shared display-mapping constants from their owner (LL-009).** The `KNOWN_STATUS_VARIANT` duplication is a generalizable DRY lesson for UI variant/label maps.
4. **Carry the arki bootstrap gaps to pattern-detector.** eslint-config-missing now appears in 2 consecutive RETROs (S12, S1). At the next pattern-detector run this should escalate to an arki prompt patch (seed eslint config + `createApp()` factory per workspace).

```markdown
## LL-007 — Validate seeded/inherited contracts against live data before freezing

- **REQ origen**: REQ-20260620-S1-registry-reader-projects
- **Síntoma**: El contrato sembrado por arki tipaba `ProjectSummary.status` como
  `z.enum([active,paused,onboarding,archived])`, pero el registro vivo contenía
  `status: mapped`. Un parse estricto habría lanzado en día uno y el contrato lo
  heredan S2–S4.
- **Causa raíz**: arki adivinó el vocabulario de un campo cuyos valores los
  posee una fuente externa (el vault), sin validar contra los datos reales.
- **Regla que aplica**: `po-analyst` en GATE0 valida cualquier campo de contrato
  que proyecte una fuente externa contra los datos vivos (lee N archivos reales,
  cuenta la distribución de valores) ANTES de escribir el REQ. Si el contrato
  sembrado contradice los datos vivos → BLOCKER, no se escribe el REQ hasta
  resolver. El `architect-reviewer` re-verifica en el freeze.

## LL-008 — Enum only fields the app owns; mirrored external fields use z.string()

- **REQ origen**: REQ-20260620-S1-registry-reader-projects
- **Síntoma**: `enums_for_states: true` empujó a sembrar un enum para un campo
  (`status`) cuyo vocabulario es del vault, no de kuraka-control.
- **Causa raíz**: Confusión entre estados que la app posee (la máquina de estados
  del triage — SÍ enum) y un campo espejo de una fuente externa (NO enum).
- **Regla que aplica**: arki y `story-refiner` aplican `enums_for_states` SOLO a
  campos cuyos valores controla la app. Para campos espejo de una fuente externa
  (frontmatter del vault, salida de scripts), usar `z.string()` (o una unión
  abierta documentada) + mapeo de display conocido en la UI con fallback neutro.

## LL-009 — Shared display-mapping constants are exported from their owner, never copied

- **REQ origen**: REQ-20260620-S1-registry-reader-projects
- **Síntoma**: `KNOWN_STATUS_VARIANT` (mapa status→variante de badge) quedó
  duplicado entre componentes (IMPORTANT en Phase 5).
- **Causa raíz**: El mapa se declaró más de una vez en vez de exportarse desde el
  componente que lo posee.
- **Regla que aplica**: `frontend-developer` declara cada mapa de variante/label
  compartido UNA vez, exportado desde su componente dueño; los consumidores lo
  importan. `code-reviewer` grepea el nombre de la constante para detectar copias.
```
