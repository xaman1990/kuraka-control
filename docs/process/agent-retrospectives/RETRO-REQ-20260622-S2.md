## 5) Workflow Improvements + Proposed Lessons

1. **Codify proactive GATE0 live-data validation as the default (candidate LL-010).** LL-007 framed live-data validation as the trigger for a *BLOCKER when a contradiction is found*. S2 showed the higher-value form: running it **proactively, before writing the REQ**, turns a would-be BLOCKED double-pass into a single clean PASS. Worth promoting from "validate when suspicious" to "validate any external-source-projecting field up front, always" — measurably shortens the cycle (S1 cost a ~40K wasted pass; S2 cost zero).
2. **State parse/compare *mechanism* decisions in the story, not as hedges.** The 2 architect MINORs (yaml-vs-JSON, segment-vs-string compare) both came from the story leaving a "Technical Note" hedge. A one-line resolved decision in the story would have spared them. (Reinforces LL-006's spirit, extended from TS-type syntax to algorithm choice.)
3. **The schema freeze pays for itself when it includes invariants, not just shapes.** SCHEMA-FROZEN-S2's *nullability biconditionals* (not just the zod) are what let code review catch an incoherent fixture. Encourage architects to freeze **invariants/decision tables**, not only field types, for any stateful computed field.
