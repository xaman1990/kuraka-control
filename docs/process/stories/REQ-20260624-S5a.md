## Exact contract (add to `packages/contracts/src/index.ts`)

```ts
// ---- S5a: RETRO Triage (READ-ONLY projection of <vault>/retro-triage/*.md) ----
// ALL vocab fields mirror externally-owned vault values → z.string(), NO z.enum (LL-008).
// Map known values → UI variant at the component layer with a neutral fallback.

/** One row of a triage doc's findings table. Externally-owned vocab → permissive. */
export const TriageFinding = z.object({
  id: z.string().nullable(),           // "#" cell: P1.. or 1.. ; null on blank
  finding: z.string().nullable(),      // description (may contain commas/parens)
  routing: z.string().nullable(),      // framework|project (md bold stripped) — UI→governance color
  target_file: z.string().nullable(),  // backticks stripped
  severity: z.string().nullable(),     // HIGH|MED|... — externally-owned
  status: z.string().nullable(),       // applied|pending|... — externally-owned
});
export type TriageFinding = z.infer<typeof TriageFinding>;

/** One triage doc = frontmatter meta + findings + rationale prose. */
export const TriageDoc = z.object({
  id: z.string(),                      // filename minus ".md" (e.g. "2026-06-06-sie_v2")
  project: z.string().nullable(),
  source: z.string().nullable(),
  date: z.string().nullable(),         // YYYY-MM-DD verbatim, NOT a Date
  decision: z.string().nullable(),     // pending|applied|rejected|deferred — externally-owned
  applied: z.boolean().nullable(),
  tags: z.array(z.string()),           // [] never null
  findings: z.array(TriageFinding),    // [] when table absent/all-blank
  rationale: z.string().nullable(),    // raw md under "## Decisions & rationale"
});
export type TriageDoc = z.infer<typeof TriageDoc>;

export const TriageListResponse = z.object({
  docs: z.array(TriageDoc),
  empty: z.boolean(),                  // true ⇔ docs.length === 0 (api-contract: empty≠error)
});
export type TriageListResponse = z.infer<typeof TriageListResponse>;
```

## Acceptance Criteria

### Backend — reader + parser
- B1: `backend/src/domain/triage.ts` exports a pure parser (no fs/env) taking raw
  file text → `TriageDoc` (sans `id`, which the reader sets from filename). Never throws.
- B2: Frontmatter via `gray-matter`; map `project/source/date/decision/applied/tags`
  per contract; `""`→`null`; missing→`null`; `tags` default `[]`.
- B3: **Table parse mechanism (LL-011, implement exactly):** (a) find header row by
  presence of `Finding`+`Routing` header cells (trim, case-insensitive); (b) skip
  the `|---|` separator row (cells only `-`/`:`/space); (c) for each following `|`-line,
  split on `|`, drop outer empty cells, `trim()` each; (d) skip rows whose cells are
  all empty (template blanks like `| 2 | | | | | |`); (e) strip surrounding `**bold**`
  from routing/severity/status and surrounding backticks from target_file, empty→null;
  (f) map by column order to the 6 fields; short/long rows degrade (fill null / ignore
  extras), never throw; (g) stop at first blank line or next `##` after the body.
- B4: Capture text under `## Decisions & rationale` (until next `##` or EOF) →
  `rationale` (raw md); none→`null`. `## Follow-up` ignored.
- B5: `backend/src/repositories/triageReader.ts` lists `<vault>/retro-triage/*.md`,
  **excludes any file whose basename starts with `_`** (the template). Reads+parses
  each; sets `id` = basename minus `.md`. A per-file error is skipped + logged to
  stderr (mirror `projectRegistry`), never aborts the batch.
- B6: Missing/unreadable `retro-triage` dir → throw the existing `VaultUnreadableError`.
- B7: `backend/src/services/triageList.ts` returns `{ docs, empty: docs.length===0 }`.
- B8: `backend/src/routes/triage.ts` `createTriageRouter({vaultRoot?})` exposes
  `GET /triage` → 200 `TriageListResponse` | 500 `ApiError(VAULT_UNREADABLE)`
  (same envelope/shape as projects route). Mounted under `/api` in `index.ts`.

### Contract
- C1: Add `TriageFinding`, `TriageDoc`, `TriageListResponse` exactly as above.
- C2: NO `z.enum` for routing/severity/status/decision (LL-008). snake_case 1:1
  with the vault source. Both sides infer types from these schemas only.

### Frontend — board
- F1: New route `/triage` → `TriagePage` wrapped in `AppShell activePath="/triage"`.
  In `AppShell.tsx`, give the "RETRO Triage" nav item `href: "/triage"` so it
  activates. Register route(s) in `main.tsx`.
- F2: `frontend/src/api/triage.ts` `fetchTriage()` parses with `TriageListResponse`;
  on HTTP error extracts the `ApiError` envelope (mirror `api/projects.ts`).
- F3: Board = a responsive **grid of `TriageCard`s**, one card **per finding**
  flattened across all docs; each card carries its parent doc's `project`+`date`.
- F4: `frontend/src/components/TriageCard.tsx` (240px) renders, per the pencil ref:
  Title = `finding` ($text 13) · Meta row = routing badge + severity badge ·
  Target = `target_file` ($text-3 11). Clicking a card opens the parent doc's detail.
- F5: **Two-color routing badge (governance):** routing → `GovernanceBadge`.
  Normalize at the component: value containing `"framework"` → `governance="framework"`
  (gold), else `governance="project"` (jade). `null` routing → neutral `Badge`.
- F6: Severity/status → neutral `Badge` with a known→variant map declared ONCE and
  exported from its owning component (LL-009); UNKNOWN value → neutral fallback, never crash.

### Frontend — detail
- D1: Detail view shows the FULL doc: meta (project/source/date/decision/applied/tags),
  a table/list of ALL findings (id/finding/routing/target_file/severity/status), and
  the `rationale` rendered as markdown/preformatted text.
- D2: Detail is fed from the already-fetched list (select by `id`); **no extra backend
  call** (REQ §4 decision). May be a client route `/triage/:id` or an in-page panel —
  implementer's choice, consistent with the design system.

### Empty / error states
- E1: `empty: true` (no real cards) → first-class empty state on the board
  ("No triage cards yet"), not a spinner/blank.
- E2: VAULT_UNREADABLE (500) → friendly error state showing the envelope message
  (mirror ProjectsPage error handling).
- E3: A doc with malformed frontmatter or table still appears with whatever parsed
  (per-doc degrade); a doc with zero parseable findings shows in detail with an
  empty findings list (no card on the board for a finding-less doc is acceptable).

### Tests
- T1: Domain tests (`triage.test.ts`): header-find, separator-skip, blank-row-skip,
  `**bold**`/backtick strip, short-row & long-row tolerance, rationale capture,
  missing-table → `findings: []`.
- T2: Reader tests (`triageReader.test.ts`) vs temp dir: `_TEMPLATE.md` excluded,
  empty store → `[]`, one malformed file degraded (batch survives), `id` from filename.
- T3: Route/service: `GET /api/triage` → 200 shape + `empty` flag; missing dir → 500
  VAULT_UNREADABLE.
- T4: `TriageCard.test.tsx`: routing `framework`→gold governance badge,
  `project`→jade, unknown severity → neutral fallback (no crash).
- T5: Phase 6.8 runtime smoke: board renders the live `sie_v2` findings; empty state
  renders when the store has no real card.
