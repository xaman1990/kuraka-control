# REQ-20260625-S5b-1: WriteFirewall foundation + route/defer/reject triage actions

## Description

As the Kuraka Control Plane operator, I want to route, defer, and reject individual
triage findings and whole cards through governed write actions, so that the RETRO
improvement loop advances its state machine on disk with an audited, path-safe single
writer.

Smoke flow: start the dev server pointing `vaultRoot` at a TEMP copy of the vault;
POST `/api/triage/2026-06-06-sie_v2/route` with `{ finding_id: "P1", routing: "project" }`;
verify 200 returns a fresh `TriageDoc` with that finding's routing column updated to
`project`; assert no write occurred in the real vault.

## Acceptance Criteria

### Backend — WriteFirewall

1. [ ] `backend/src/repositories/writeFirewall.ts` is the ONLY module in the backend
   that calls `fs.writeFile`, `fs.rename`, `fs.mkdir`, or `fs.rm`. A project-wide grep
   for `fs\.(writeFile|rename|mkdir|rm)` must match ONLY this file.
2. [ ] The firewall exposes one public async function:
   `writeTriageRecord(triageDirAbsPath: string, filename: string, content: string): Promise<void>`.
   It accepts only `triage_record`-class writes in S5b-1; `framework_patch` and
   `project_patch` are stubbed stubs that immediately throw `PATH_FORBIDDEN`.
3. [ ] **Containment mechanism** (exact, copy-ready): given `triageDirAbsPath` and
   `filename`, the firewall (a) resolves `triageDirAbsPath` to an absolute real path
   via `fs.realpath(triageDirAbsPath)` (resolves symlinks on the parent directory
   before the new file exists); (b) constructs the candidate absolute path as
   `path.join(realDir, filename)`; (c) asserts `candidatePath.startsWith(realDir + path.sep)`
   OR `candidatePath === realDir` — if not, throws `WriteFirewallError` with code
   `PATH_FORBIDDEN`; (d) asserts `filename` matches the regex
   `^\d{4}-\d{2}-\d{2}-[a-z0-9_-]+\.md$` — if not, throws `WriteFirewallError` with
   code `PATH_FORBIDDEN`. Only after both assertions pass does it write.
4. [ ] **Atomic write**: the firewall writes `content` to a temp file
   `<realDir>/<filename>.tmp` via `fs.writeFile`, then renames it to
   `<realDir>/<filename>` via `fs.rename`. A failure after `writeFile` but before
   `rename` leaves only the `.tmp` file; the original card is never truncated.
5. [ ] **Hard denials** — the firewall throws `WriteFirewallError` (code
   `PATH_FORBIDDEN`) without writing for: (a) any path whose realpath does not start
   with the expected triage dir; (b) a filename containing `..`, `/`, or `\`;
   (c) a filename that fails the `^\d{4}-\d{2}-\d{2}-[a-z0-9_-]+\.md$` regex
   (e.g. `_TEMPLATE.md`); (d) any consumer `backend/` or `frontend/` absolute path.
6. [ ] `WriteFirewallError` is a typed class with `code: "PATH_FORBIDDEN" | "WRITE_FAILED"`
   and `message`; it is the only error the firewall propagates intentionally. Unexpected
   `fs` errors (disk full, perms) are wrapped and thrown as `WriteFirewallError` with
   code `WRITE_FAILED`.
7. [ ] Module-level constants used: `TRIAGE_FILENAME_REGEX` (the pattern in AC3d),
   `TRIAGE_RECORD_DIR` = `"retro-triage"` (the vault subdirectory name). No magic
   strings inside the write function body.

### Backend — Domain (`triage.ts`)

8. [ ] A new **pure** exported function `setFindingCell` is added to
   `backend/src/domain/triage.ts` with signature:
   `setFindingCell(rawText: string, findingId: string, column: 2 | 5, value: string): string`.
   It returns the full updated raw document text. It never throws on missing-finding
   (returns the original text unchanged so the service can detect no-op).
9. [ ] **Surgical single-cell rewrite algorithm** (exact, copy-ready): (a) parse the
   raw text with `matter(rawText)` to obtain `body`; (b) split `body` into lines;
   (c) locate the header line using the same anchor as `parseTriageFindings` — first
   `|`-starting line whose `splitPipeLine`+`.toLowerCase()` cells include both
   `"finding"` and `"routing"`; (d) skip the separator row immediately after; (e) scan
   body rows: for each `|`-starting row, call `splitPipeLine` and apply
   `emptyToNull(stripBold(cells[0]))` to get the row's id — compare to `findingId`
   (exact string match, no case fold); (f) when the target row is found, split the
   **original raw line** on `"|"`, replace ONLY the cell at position `column + 1`
   (accounting for the leading empty split artifact from the leading `|`) with ` value `
   (space-padded to one space on each side), re-join with `"|"`, re-assemble the full
   document via `matter.stringify(parsedBody, data)` with the modified body; (g) all
   other cells and all other lines are preserved byte-for-byte. Write plain `value` —
   no `**bold**` wrapper added. The S5a parser strips bold on read; plain values
   round-trip correctly.
10. [ ] `setFindingCell` is idempotent: calling it twice with the same `findingId` and
    `value` produces the same output as calling it once.
11. [ ] A new pure exported function `setFrontmatterDecision` is added:
    `setFrontmatterDecision(rawText: string, decision: string, applied?: boolean): string`.
    It uses `matter(rawText)` to parse, sets `data.decision = decision` and optionally
    `data.applied = applied`, then returns `matter.stringify(parsed.content, data)`.
    It does NOT touch the body (findings table, rationale).

### Backend — Actions Service (`triageActions.ts`)

12. [ ] `backend/src/services/triageActions.ts` exports three functions:
    `routeFinding`, `deferTriage`, `rejectTriage`. Each accepts
    `{ id: string, finding_id?: string, vaultRoot: string }` and returns
    `Promise<TriageDoc | "NOT_FOUND" | "BAD_REQUEST">`.
13. [ ] `routeFinding` also accepts `routing: "framework" | "project"` in its input.
    When `finding_id` is absent it returns `"BAD_REQUEST"` (route is finding-scoped
    only; a card has no single routing). When `finding_id` is present it calls
    `setFindingCell(rawText, finding_id, 2, routing)` and writes via the firewall.
14. [ ] `deferTriage`: when `finding_id` is present, calls `setFindingCell(rawText, finding_id, 5, "deferred")`
    and writes. When absent, calls `setFrontmatterDecision(rawText, "deferred")` and writes.
15. [ ] `rejectTriage`: when `finding_id` is present, calls `setFindingCell(rawText, finding_id, 5, "rejected")`
    and writes. When absent, calls `setFrontmatterDecision(rawText, "rejected")` and writes.
16. [ ] Each action function: (a) reads the card via `fs.readFile` using the path
    `path.join(vaultRoot, "retro-triage", id + ".md")`; (b) returns `"NOT_FOUND"` if
    the file does not exist (`ENOENT`); (c) calls the domain transformation; (d) if
    `setFindingCell` produced no change (output === input) AND `finding_id` was
    provided, returns `"NOT_FOUND"` (unknown finding_id); (e) delegates the write to
    `writeTriageRecord`; (f) re-reads the written file and re-parses it with
    `parseTriageDoc`, returning the fresh `TriageDoc` with `id` set. The response is
    always disk truth, never an in-memory echo.
17. [ ] `WriteFirewallError` with code `PATH_FORBIDDEN` propagates up without catching;
    the route layer maps it to 403. `WriteFirewallError` with code `WRITE_FAILED`
    propagates to 500 `WRITE_FAILED`.

## API Contract

### POST /api/triage/:id/route

**Request:**
```json
{ "finding_id": "P1", "routing": "framework" }
```

**Response 200:**
```json
{ "doc": { "id": "2026-06-06-sie_v2", "decision": "pending", "findings": [...] } }
```

**Errors:** 400 `BAD_REQUEST` (invalid body or missing `finding_id`), 403 `PATH_FORBIDDEN`
(firewall), 404 `NOT_FOUND` (unknown card or finding_id), 500 `WRITE_FAILED` / `VAULT_UNREADABLE`

### POST /api/triage/:id/defer

**Request:** `{}` or `{ "finding_id": "P1" }`

**Response 200:** `{ "doc": { ...TriageDoc... } }`

**Errors:** 403 `PATH_FORBIDDEN`, 404 `NOT_FOUND`, 500 `WRITE_FAILED` / `VAULT_UNREADABLE`

### POST /api/triage/:id/reject

**Request:** `{}` or `{ "finding_id": "P1" }`

**Response 200:** `{ "doc": { ...TriageDoc... } }`

**Errors:** 403 `PATH_FORBIDDEN`, 404 `NOT_FOUND`, 500 `WRITE_FAILED` / `VAULT_UNREADABLE`

**All 403 `PATH_FORBIDDEN` detail:** `{ "id": "<card-id>" }` — never the absolute path.

## Technical Notes

- **Import path for tests**: existing test files use `"../repositories/triageReader.js"`
  (relative, `.js` extension). Confirmed from
  `backend/src/repositories/triageReader.test.ts`. Use the same convention in all new
  test files: relative path with `.js` extension.
- **`matter.stringify` signature**: `matter.stringify(content: string, data: object) → string`.
  In `setFrontmatterDecision` and `setFindingCell`, call it as
  `matter.stringify(parsed.content, { ...parsed.data, decision: ... })`. Do not call
  `matter.stringify(rawText, data)` — that would double-serialize the frontmatter block.
- **No `enums_for_states` in contract read fields**: per LL-008, `TriageFinding.routing`
  and `TriageFinding.status` stay `z.string().nullable()`. Only `TriageRouting` (the
  action request input) is a `z.enum`.
- **`setFindingCell` column indexing**: raw `split("|")` on a line like
  `| P1 | desc | framework | file | HIGH | pending |` produces
  `["", " P1 ", " desc ", " framework ", " file ", " HIGH ", " pending ", ""]`.
  The leading/trailing empty strings are index 0 and 7. Column `[2]` Routing is at
  split-index 3; column `[5]` Status is at split-index 6. The implementation must
  account for this offset (leading `|` produces an empty first element).
- **LOC budget**: `writeFirewall.ts` is expected to be ~80–100 LOC; `triageActions.ts`
  ~100–120 LOC; `routes/triage.ts` additions ~60–80 LOC. All within `max_file_loc: 400`.
- **S5b-2 is OUT**: `apply`, `confirm_token`, RL-5 conflict serialization, and
  `framework_patch` / `project_patch` write classes are explicitly deferred. The
  `writeTriageRecord` signature in S5b-1 should accept `triageDirAbsPath` and
  `filename` separately so S5b-2 can add `writeFrameworkPatch` without changing the
  S5b-1 public surface.
