# REQ-20260622-S2: Project Detail header + drift indicator

## Description

As a Kuraka operator, I want to open `/projects/:name` and see the project's
header with a live drift indicator showing whether the mounted framework version
matches the vault's current version, so that I can immediately assess whether a
project is up to date or unmanaged without leaving the app.

**Smoke-flow:** navigating to `/projects/kuraka-control` renders the Sidebar +
header (breadcrumb / name / GovernanceBadge / DriftBadge) and reads
`GET /api/projects/kuraka-control` (200 `ProjectDetail`); navigating to
`/projects/sie_v2` renders the same header with a neutral `not_pinned` badge
(no `kuraka.lock` on disk).

1. [ ] `packages/contracts/src/index.ts` — add (exact zod):

```ts
export const DriftState = z.enum([
  "up_to_date",
  "behind",
  "ahead",
  "not_pinned",
  "unknown",
]);
export type DriftState = z.infer<typeof DriftState>;

export const Drift = z.object({
  state: DriftState,
  lock_version: z.string().nullable(),
  vault_version: z.string().nullable(),
  registry_version: z.string(),
  registry_matches_lock: z.boolean().nullable(),
});
export type Drift = z.infer<typeof Drift>;

export const ProjectDetail = ProjectSummary.extend({ drift: Drift });
export type ProjectDetail = z.infer<typeof ProjectDetail>;
```

### Backend — Domain

7. [ ] `backend/src/domain/drift.ts` — pure function (no fs, no env):

```ts
export function computeDrift(
  lockVersion: string | null,
  vaultVersion: string | null,
): DriftState
```

8. [ ] `computeDrift` implements the comparison rule exactly:
   - `lockVersion === null` → `"not_pinned"` (short-circuits; does not evaluate `vaultVersion`).
   - `vaultVersion === null` → `"unknown"`.
   - Both parseable as semver (`major.minor.patch`): compare numerically.
     - equal → `"up_to_date"`, lock < vault → `"behind"`, lock > vault → `"ahead"`.
   - Either present but not parseable as semver → `"unknown"`. Never throws.

## Technical Notes

- **No new npm packages.** `kuraka.lock` is YAML/JSON; parse with `js-yaml`
  (already a transitive dep) or `JSON.parse` after checking the extension.
  Prefer `JSON.parse` if the lock is plain JSON; fall back to a line-by-line read
  for YAML. Architect confirms format in Phase 3.
- **Vault version is fragile.** The anchored regex
  `/^DEFAULT_VERSION\s*=\s*["']([^"']+)["']/m` on `kuraka-init.py:41` is the
  only machine-readable source today. Architect should flag a follow-up story to
  add a canonical `VERSION` file to the vault.
- **No live `behind`/`ahead` data.** All projects currently on `0.3.4`. Unit-test
  `computeDrift` with synthetic versions; the live smoke test covers only
  `up_to_date` + `not_pinned`.
- **Phase 6.8 smoke:** open `/projects/kuraka-control` (expect `up_to_date` badge
  in jade/green) and `/projects/sie_v2` (expect `not_pinned` badge in muted).
  Both must render the Sidebar.
- **File-size budget.** `ProjectDetailShell.tsx` will grow; split into
  sub-components (`DetailHeader`, `TabsBar`) if it approaches 300 LOC.
- **`registry_matches_lock` semantics:** `null` when `lock_version` is null
  (nothing to compare), `true`/`false` otherwise. The frontend chip fires only on
  `false` (AC 26); it is silent when `null`.
