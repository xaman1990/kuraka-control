# REQ-20260620-S1: Registry reader + /projects grid + detail route shell

## Description

As a Kuraka operator, I want to open `/projects` and see every registered project
as a clickable card driven by live vault data, so that I can assess fleet health
at a glance and navigate to a project's detail shell.

**Smoke-flow:** when the backend reads `<vault>/projects/*.md` and exposes
`GET /api/projects`, the frontend renders a responsive grid of `ProjectCard`s at
`/projects`; clicking any card navigates to `/projects/:name` (a placeholder shell).

## API Contract

### GET /api/projects

**Request:** no body, no query params.

**Response 200:**
```json
{
  "projects": [
    {
      "name": "sie_v2",
      "path": "/Users/xmn/Desarrollos/sie_v2",
      "repo_url": "https://github.com/org/sie_v2",
      "stack": "python-fastapi / vue-pinia",
      "kuraka_version": "0.3.4",
      "has_project_layer": true,
      "default_mode": "normal",
      "focus_scope": null,
      "status": "active",
      "last_mount": "2026-06-01",
      "last_sync": null,
      "tags": ["backend", "frontend"],
      "governance": "project"
    }
  ],
  "empty": false
}
```

**Response 200 (empty vault):**
```json
{ "projects": [], "empty": true }
```

**Response 500 (vault unreadable):**
```json
{
  "error": {
    "code": "VAULT_UNREADABLE",
    "message": "Cannot read the Kuraka vault",
    "detail": { "path": "/Users/xmn/Documents/Agentes/AgentesTrabajos/kuraka" }
  }
}
```

## Technical Notes

- `governance: z.literal("project")` is a derived constant in the contract, not
  read from frontmatter. All registry projects are jade/project-native. This
  satisfies `ProjectCard`'s existing `GovernanceBadge` without frontend logic.
- `z.coerce.string()` for `kuraka_version` handles YAML parsing a bare `0.3` as
  the number `0.3` rather than the string `"0.3"`.
- Per-file fault tolerance: `gray-matter` throws on truly malformed YAML. Catch
  per file in the repository layer, log to `stderr`, push the filename to a
  `skipped[]` array — do not rethrow. The service layer may include skipped files
  in a `detail` key of the response (optional for S1; note it in the server log at
  minimum).
- The `Sidebar` in `ProjectsPage` is a self-contained layout component for S1.
  Do NOT extract it as a shared layout yet — that refactor belongs to the story
  that introduces the second page with a sidebar (likely S2 or S8). Keep it
  co-located in `ProjectsPage.tsx` for now (within 300 LOC limit).
- Inert nav items: render with `aria-disabled="true"` and no `to` prop (or
  `to="#"`). This prevents broken navigation without hiding the intended information
  architecture from the operator.
- Vault path is read from `env.vaultRoot` (already in `backend/src/config/env.ts`).
  No new env variable is needed.
- `KNOWN_STATUS_VARIANT` in `ProjectCard.tsx` must be a module-level `const`
  (not inlined in the render function) — required by Rule 11 (explicit constant
  naming in AC).
